# BLOCK tests — block-level replay and cache breakers

Package BLOCK (wave 2) owns `tokenbill/sim/block_replay.py`, `tokenbill/detect/block.py`,
`tests/v2/blocksim/**` and `tests/v2/fixtures/blocksim/**` (SPEC §9.7, §10.4, D28).

## Public API

- `sim.block_replay.BlockReplayer` — a `Replayer` for `Policy.breakpoint_policy`
  (`observed | end | static_plus_end | every_15`) and `block:` repairs (list in
  `CONTRACT-CHANGE-BLOCK-1.md`); minimal change: each request costs its billed cost minus
  `model(observed) − model(policy)`; lanes without fingerprints are skipped with a reason; other
  clauses are listed in `assumptions` as ignored.
- `BlockReplayer.predict(lanes, *, pricer, rules=None, placement="observed")` — the model's own
  predicted usage and cost per request.
- `first_divergence(prev, cur, *, rules=None) -> (tier, block index, cause) | None`,
  `salt_diff`, `chain_hashes`, `read_agreement`, `lane_skip_reason`.
- `detect.block.BlockBreakers` — registry id `block.breakers`, `requires = {"blocks"}`, the eleven
  §10.4 kinds.

## Fixtures and provenance

Every fixture is synthetic; nothing comes from real transcripts.

- `helpers.py` blocks: hashes derived from short names (`h:<name>`), `est_tokens` exact, billed
  totals equal to the block sizes — so every expected token count and nano figure in the tests is
  hand-computed from the Opus 5.5 rates of Appendix A ($4 / $0.20 / $5 / $8 per MTok).
- v0.1 demo scenarios: generated by the frozen `tokenbill.demo_traces.scenario` (seeds 7, 11) and
  fingerprinted with `fp.py` (HMAC key `tokenbill-blocksim-test-key-0001`).
- `tests/v2/fixtures/blocksim/*.jsonl`: the codebase experiments, re-encoded deterministically by
  `exps.py` from payloads built out of a fixed word list (no volatile values, no real text), with
  synthetic billed usage shaped like each experiment's billing; one header line, then one
  `core.records.to_json` lane per line. Rebuild with
  `python tests/v2/fixtures/blocksim/build_fixtures.py`; `test_fixtures.py` fails on stale files.
  exp2b-a3 uses a 20,000-character shared document and 7,300-character questions so that
  `static_plus_end` saves 56.2% of the input dollars (Sonnet 5 rates).

## Interpretations (documented choices where the SPEC is silent)

1. **Cohort-scoped sharing** — entries are shared within a `(team, lane_kind)` cohort only
   (shard invariance, D30); an `"unknown"` cache scope never shares across lanes
   (CONTRACT-CHANGE-BLOCK-1 §3).
2. **Sizing** — block `est_tokens` rescaled per request to billed `total_input`; a cache hit reads
   the size its entry recorded when written (clamped; the whole total when the hit covers every
   block). This makes the model reproduce working-cache billing exactly (agreement 1.0 on
   `well-behaved` and exp1).
3. **Parameter comparisons** — consecutive requests of a lane are compared exactly as
   `core.transitions` compares request `i` with `i − 1`, in `first_divergence`, `salt_diff` and
   the chain build alike: a salted parameter only one of them reports is no change (so effort
   high → unreported → low breaks nothing), and both salts use the **later** request's effort
   exemption (`effort_change_keeps_cache` is evaluated for request `i`), so an exemption that
   flips (a Claude Code upgrade past 2.1.260, a per-message effort beta added) with an unchanged
   effort breaks nothing, and an effort change counts exactly when the usage level calls it
   `effort-change` (a hypothesis test checks the agreement). A request's own node salts (new
   chain nodes, cross-lane sharing) fill unreported parameters from the lane's nearest reported
   value. Served speed is taken from the serving inference.
4. **Lookups** — each breakpoint looks back ≤ 20 collapsed positions (its own first) for the
   deepest live, visible entry; every entry a lookup finds is refreshed (its own TTL) and counts as
   read; the request reads up to the deepest hit; entries are created only at breakpoints beyond it
   (at the breakpoint's TTL, if the prefix meets the minimum). A concurrent re-write of an entry that
   is not yet visible is a fan-out: both pay, the entry keeps the earliest visibility.
5. **Static prefix** — the deepest block whose prefix a request of another lane of the cohort also
   sends, else the end of the lane's common prefix (hindsight over the replayed lanes).
6. **every_15** — static + the largest positive multiples of 15 collapsed positions below the end +
   end, within 4 breakpoints: lookback-safe for turns adding up to ~45 positions.
7. **Placement TTL** — the request's last observed breakpoint TTL, else the lane's most common one,
   else 5m.
8. **Outcome usage** — for a changed request, billed usage shifted by the model delta when every
   bucket stays ≥ 0, else the policy prediction; the cost is always billed − delta.
9. **Breaker triggers** — a divergence is a breaker only inside the previous request's cached
   prefix and without a compaction/clear/context-edit event between; compaction blocks, applied
   edits and dropped thinking are expected rebuilds; model switches are usage-level. Lookback
   overflow, write-never-read and fan-out need billed confirmation (a billed miss / billed writes).
   Write-never-read counts single-writer entries of one-shot lanes or shadowed breakpoints (not a
   lane's final write, not after an idle gap, not after the successor diverged, not an overflow
   miss), and `block:drop_unread` drops exactly those breakpoints, so its recoverable never
   includes what the TTL levers, a divergence repair, `every_15` or `block:stagger` recover.
   Fan-out events are the concurrent re-writes whose own billed writes confirm them. Placement is evaluated on lanes with markers and no other breaker (so a lane gets the
   specific diagnosis, not a generic one).
10. **Money** — `cost_observed` is billed arithmetic on the affected requests (uncached + write
    input; all input for placement; writes for write-never-read and fan-out); `recoverable` is the
    replay saving (ESTIMATED, UNCALIBRATED; the block engine has no calibrated mode), floored at 0
    with "no recovery modeled — billed caching already beats the simulated fix"; fan-out savings
    are upper bounds; `min_usd` gates the recoverable point (the observed cost for kinds without a
    repair).

## Performance

A 4,000-call growing conversation (4,002 blocks at the end, one breakpoint on the newest block)
replays under `breakpoints=every_15` in ≈ 0.35 s on the build machine (baseline pricing included),
against the 2 s budget; the chain build compares delta-shared block tuples at C speed and interns
only new blocks, the static prefix walk is memoized per node. When consecutive requests carry equal
but distinct block objects (a reader that decodes each request independently), the build compares
per-request hash-key lists instead (O(prefix) per request at C speed, keeping only the newest
list): ≈ 0.7 s for the same run.

## Known limits

- The replay saving is a point at the pricer's unit (low) rates; when a request's pricing is a
  range (unknown endpoint scope, unknown TTL), the cost range is the baseline range minus that
  point (SPEC §6.4: unit rates are the point rates).
- Providers that cache prefixes automatically without markers (OpenAI) are modeled only when the
  adapter sets `automatic_caching`; no v0.2 adapter fingerprints OpenAI payloads (§5.8).
- `write-never-read` can co-fire with `breakpoint-placement` on one-shot shared-prefix lanes
  (exp2b-a3): both are true (the question write is never read; the shared prefix should be
  marked) and both link the `blocks.breakpoints` lever.
- trace@1 lane inference (§5.5/§5.8) as written would split the `tool-churn` demo run by tool
  order; see CONTRACT-CHANGE-BLOCK-1 §4.
