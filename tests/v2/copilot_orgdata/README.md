# tests/v2/copilot_orgdata — CP-ORGDATA acceptance tests

Package CP-ORGDATA (wave 2b, GitHub Copilot): GitHub's Copilot configuration and activity data as
content-free, pseudonymized records Token Bill can join — the primary, release-blocking org-data
path (no laptop collection; covers VS Code and JetBrains users alike).

| module | registry name / API |
|---|---|
| `tokenbill/adapters/github_config.py` | `CopilotConfigAdapter` (`github-copilot-config`); also the shared org-data reader (`OrgRead`, `iter_documents`), `login_key`, strict parsers |
| `tokenbill/adapters/github_metrics.py` | `CopilotMetricsAdapter` (`github-copilot-metrics`), `ide_key`, `model_key` |
| `tokenbill/adapters/github_seats.py` | `CopilotSeatsAdapter` (`github-copilot-seats`), `bucket_of` |
| `tokenbill/adapters/github_agent_tasks.py` | `AgentTasksAdapter` (`github-agent-tasks`) |
| `tokenbill/adapters/github_usage_records.py` | `UsageRecordsRefusal` (`github-usage-records`) |
| `tokenbill/copilot/teammap.py` | `build_maps(user_teams, cost_centers, *, k=5) -> (team_map, cost_center_map)`, `user_team_records` |

Run: `uv run --python 3.12 --extra dev pytest -q tests/v2/copilot_orgdata` (also `--python 3.10`).
Coverage: `uv run --python 3.12 --extra dev coverage run -m pytest tests/v2/copilot_orgdata && uv run
--python 3.12 --extra dev coverage report --include='tokenbill/adapters/github_*.py,tokenbill/copilot/teammap.py'`
(96 % at hand-off). Fuzz: `TB_ORGDATA_FUZZ_EXAMPLES=2500 uv run … pytest tests/v2/copilot_orgdata/test_fuzz.py`

## Fixtures (`tests/v2/fixtures/copilot_orgdata/`, generated by `build_fixtures.py`)

Every fixture is **synthetic**; provenance class **primary-derived**: shapes and field names are
copied field for field from GitHub's GHEC OpenAPI description (`ghec.json` 1.1.4, opened
2026-09-23: budgets, user-states, cost centers, org Copilot billing, seats, agent tasks, usage
records) and from the Copilot usage-metrics field reference and example-schema pages (opened
2026-09-23); every value is invented. `CANARY_LOGIN` is planted in logins (`user_login`,
`assignee.login`, budget `user`, alert recipients, user-states, cost-center `User` resources),
`CANARY_EMAIL` in e-mails, `CANARY` in names, prompts, branch names, team descriptions, repository
names, masked MCP names and usage-record bodies.

## Behavior worth knowing (decisions the briefs left open)

- **Inputs.** A JSON document (object or array), NDJSON / JSONL, `.gz`, a CP-PULL envelope
  `{"request": {"path"|"url", "query"}, "response": body | {"status", "headers", "body"}}` (a body
  given as JSON text is parsed), an `{endpoint|url|path, response|page}` wrapper, or a directory
  of `*.json|*.jsonl|*.ndjson[.gz]` files read as one source (`manifest.json`, hidden files and
  other files skipped). Recorded request paths and queries are used only to classify documents and
  to name the budget id, org or repository; they are never stored.
- **Login normalization** (shared contract, see CONTRACT-CHANGE-CP-ORGDATA.md item 4):
  `p_ = core.ids.pseudonym(principal_key, "p", login.strip().lower())`; the team and cost-center
  maps are looked up exactly, then case-folded (login first, then the numeric user id). Identity
  modes `central-ingest` and `install` only; a missing principal key is a `UsageError` as soon as
  a person record is met. Content tier other than `none` → `UsageError`; a name key is required.
- **Fetch time.** Envelope `fetched_ms` / `fetched_at`, else `opts.now_ms`; it is the
  `snapshot_ms` / `fetched_ms` of every record (latest fetch wins per natural key, in the read and
  in the record store). Seats without either use the latest timestamp of the source as snapshot
  date (`dq.copilot_snapshot_date_assumed`).
- **Budgets.** Attrs omit `None` values. `target`: `enterprise` (enterprise and
  multi_user_customer scopes), `org:<name>`, `cc:<name>` (cost_center and multi_user_cost_center),
  `repo:h_…`; user scope has no target but the user's `team` / `cost_center` (unmapped → absent)
  and `consumed_nano`; a budgets page filtered by `?user=` gives multi-user budgets that user's
  team / cost center and consumption. `amount_nano` is omitted for license-based SKUs (seat and
  Code Quality license SKUs: GitHub counts licenses there, `stats["license_budget_amounts_not_stored"]`).
  Unknown enum values are dropped (`stats["unknown_enum_values"]`).
- **User-states.** All pages of one budget in one read are summed; the budget id comes from the
  request path (else `budget_id`), without it the page is quarantined
  (`dq.copilot_budget_users_unattributed`). `n_at_or_over_target` = consumed ≥ target; p50 / p90
  are nearest-rank, only with ≥ `opts.k_anonymity` users.
- **Cost centers.** `pool_target_credits` / `pool_current_credits` are ints when integral, else the
  exact decimal string (as `core.pool` reads them); `azure` is a bool (the subscription id is never
  stored); resource names are never read.
- **Org settings.** The org login comes from the request path (`/orgs/{org}/copilot/billing`) or
  `--attr workspace_id=<org>`, else the record is quarantined (`missing:org`,
  `dq.copilot_org_unknown`); `public_code_suggestions` is not a config key and is dropped.
- **Metrics mapping.** Exactly the addendum §5.5 table; keys present in the source are kept even
  when 0 (`ide:vscode: 0` says "used VS Code for completions only"); `feature:<f>` and `model:<id>`
  = interactions + generations, `ide:<ide>` = interactions; undocumented feature values count as
  `feature:others`; `model:` keys use `core.models.normalize_copilot_model` (pseudo labels →
  `unknown`). A user-day seen twice in one read is kept once (`stats["duplicate_records"]`).
- **Team outcome rows** per (source kind, day): unmapped people form the `(unmapped)` group; groups
  below k merge into `(other)` or are dropped (`dq.outcomes_suppressed`, `stats["users_dropped"]`).
  Entity rows: `(enterprise)` for records without `organization_id`, `(org:<org>)` otherwise (org
  from the request path or `--attr`, else the numeric `organization_id`), `n_users` =
  `daily_active_users`, `pull_requests` = `total_merged`, `extra` per `OUTCOME_EXTRA_KEYS`.
  Repos files give one PR total per day under source kind `github.copilot_metrics.repos`
  (`(org:<org>)` when the request path is an org's), so they never collide with the aggregated
  report's row.
- **28-day files.** Source kind `github.copilot_metrics.28day` for activity (dated
  `report_end_day`) and outcomes (`day_totals` entries keep their own days), both dq codes counted
  per accepted record. A daily row wins over a 28-day row of the same person and day in one read
  (`stats["activity_28day_superseded"]`); across reads see CONTRACT-CHANGE item 1.
- **Seats.** One snapshot per (principal, org); two seats of one person in one org (e.g. two
  enterprise teams) merge (most recent activity, direct assignment wins, earlier creation date,
  Enterprise over Business). `seat_created` is the UTC date of `created_at`.
- **Agent tasks.** `repo` dim = `h_` of `owner/repo` from the request path (the AI usage report's
  `repository` spelling), else `h_` of `id:<repository id>`; `team` = the session user's (else the
  task creator's) numeric id through `opts.team_map` — login-keyed maps give `(unmapped)`;
  `usage.amount` must be a whole number of nano-credits; states outside the documented set →
  `unknown`; terminal states are `final`. Bare pages (no envelope) are treated as repository pages.
- **Usage records** are never parsed: records are counted by `"github_request_id":` keys in the
  raw bytes (an escaped key inside a body string does not count).
- **Data-quality codes emitted:** `dq.unknown_fields`, `dq.outcomes_suppressed`,
  `dq.copilot_28day_window`, `dq.copilot_dashboard_export`, `dq.copilot_legacy_metrics`,
  `dq.copilot_legacy_pru`, `dq.copilot_agent_tasks_user_scope`, `dq.raw_bodies_ignored` (named in
  the briefs) and, new, `dq.copilot_org_unknown`, `dq.copilot_budget_users_unattributed`,
  `dq.copilot_snapshot_date_assumed`, `dq.copilot_agent_tasks_coverage`.
- **R-E43** (billing path on every Copilot inference): these adapters emit no requests or
  inferences, so no billing path is set anywhere.

## Unverified facts (VERIFY; shipped as labelled assumptions)

1. **JetBrains editor strings** — seat `last_activity_editor` values for JetBrains IDEs and metrics
   `ide` values other than `intellij` (`pycharm`, `goland`, `rider`, …) map to `jetbrains` through
   `core.catalog.editor_family` (facts `copilot.editor_families`, `verified: false`, addendum
   §19.5 #22). The fixture's `JetBrains-IU/…/copilot-intellij/…` string is invented.
2. **Usage-dashboard NDJSON export shape** (addendum §19.5 #34) — accepted only in the API 28-day
   shape; nothing tells a dashboard export from an API 28-day file, so every 28-day record carries
   both dq codes.
3. **CP-PULL envelope details** — the response as `{status, headers, body}` and `fetched_ms` /
   `fetched_at` keys are accepted but not fixed by CP-PULL's brief; a bare response works too.
4. **`last_authenticated_at: null`** is read like `last_activity_at: null` (`none_90d`); the API
   documents nil-after-90-days only for activity.
5. **Budget amounts of license-based SKUs** — ghec.json says "for license-based products, this
   represents the number of licenses"; which SKUs count as license-based is taken from facts
   `copilot.skus` (seat and Code Quality license cost types).
6. **Cost-center resource type spellings** — `User`, `Team`, `Repo` are documented; `Org` /
   `Organization` / `Repository` are accepted by assumption.
7. **Agent-task sessions** — `usage.amount` in nano-credits (ghec.json) and `premium_requests`
   before 2026-06-01; session and task `user` / `creator` carry only numeric ids.
8. **Team size for `build_maps`** — the largest number of members on one day of the input (GitHub
   omits teams below 5 seated users per day).
