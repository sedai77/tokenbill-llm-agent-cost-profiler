### B1. `cc.version_floor`: move the Claude Code fleet off old client versions (lever) + `cc.version-skew` (detector)

- **Why:** several cost facts are now *client-version gated*:
  - Opus 5.5 availability and the `opus`/`default` alias flip need ≥ 2.1.280 (A3). This is the biggest price cut of the quarter.
  - Four cache breakers were fixed in 2.1.281:
    - a resume during a pending permission prompt that "broke the prompt cache from that point";
    - "prompt cache being lost when an MCP server disconnects mid-conversation … while tool search is off";
    - resumed sessions "re-sending earlier turns in a changed form";
    - the auto-mode classifier rewriting instead of reusing its cache after a resume.
  - A runaway fix, also 2.1.281: "a turn that could retry indefinitely, ignoring `--max-turns`".
  - A duplicate-context fix, also 2.1.281: "CLAUDE.md and rules files from an `--add-dir` directory … sent to the model twice in headless and SDK sessions".
  - Enterprises that choose `autoUpdatesChannel: "stable"` (2.1.274 today) lag by about a week, and unmanaged laptops lag longer.
- **Inputs:**
  - `client_version` per request, already captured from OTel `app.version` and transcripts.
  - Spend per lane.
  - The existing `cache.miss-by-cause` events with `messages_changed` or `tools_changed` at resume boundaries.
  - MCP-server disconnect events (B7).
  - The `max_turns` or stop pattern for runaway turns.
- **Detection rule:**
  1. Keep a new `facts.json` table `cc_version_facts` of rows `{min_version, effect, finding_kind, source}`.
  2. For each cohort, compute the spend share on versions below each floor.
  3. Attribute spend only where the lane shows the matching symptom. For example: `default-model`/`same-tier-upgrade` on `claude-opus-5`; a resume-boundary `messages_changed` miss; a tool-search-off `tools_changed` miss after an MCP reconnect.
- **Fix sentence:** "Set `requiredMinimumVersion` to 2.1.281 (managed settings) or move this cohort's `autoUpdatesChannel` to `latest` until `stable` passes 2.1.281; this enables Opus 5.5 for `opus`/`default` and removes N resume-related cache rebuilds."
- **Savings estimate:**
  - (a) Model part: replay the affected lanes at Opus 5.5 rates. ESTIMATED, marked `needs_eval` because of behavior change.
  - (b) Cache part: the rewrite premium of the matching miss events. EXACT for spend already incurred, and an upper bound for the future.
  - (c) Duplicate-context part: count duplicate CLAUDE.md bytes in headless `--add-dir` sessions × turns × read rate.
- **Verify:** `managed_settings_resolved` events (D3) show the floor is live. Pre/post by version cohort.

### B3. `cc.auto_mode_server`: stop paying for local auto-mode classifier calls (lever + detector)

- **Why (primary):**
  - `permission-modes` doc: "On Enterprise plans and on accounts that use the Claude API, Claude Platform on AWS, Amazon Bedrock, Google Cloud's Agent Platform, or Microsoft Foundry, **classifier calls count toward your token usage**. Each check sends a portion of the transcript plus the pending action."
  - "Where the server reviews the actions as part of the session's model requests, **there are no separate classifier calls to count**."
  - Server review is on by default for:
    - the direct API from v2.1.278 on Enterprise and API accounts (v2.1.271 on Pro, Max and Team), "as Anthropic rolls it out";
    - cloud providers and LLM gateways from v2.1.278;
    - Claude apps gateway sessions from v2.1.280;
    - telemetry-off sessions from v2.1.282.
  - It falls back to local classifier calls when "an LLM gateway or proxy … drops the request for review or the results". `CLAUDE_CODE_AUTO_MODE_SERVER=0` forces local calls. v2.1.281 also made the classifier reuse its prompt cache after a resume.
- **Inputs:**
  - OTel `api_request`/`cost.usage` with `query_source` of the classifier. It is expected under `auxiliary`, but the exact label is **VERIFY** on a real export.
  - `claude_code.permission_mode_changed` events showing auto mode.
  - The env var and `ANTHROPIC_BASE_URL` presence from the policy snapshot.
  - `client_version`.
- **Detection rule:** in auto-mode sessions, classifier-attributed cost > 0 **and** (version below the floor for that connection type, **or** a gateway in the path, **or** `CLAUDE_CODE_AUTO_MODE_SERVER=0`).
- **Fix sentence:** "Upgrade to ≥ 2.1.281 and let the server review auto-mode actions (unset `CLAUDE_CODE_AUTO_MODE_SERVER=0`; make the gateway pass review requests and results through), which removes the separate classifier calls."
- **Savings estimate:** the observed classifier cost. EXACT from OTel `cost_usd`, fully recoverable where server review is available.
- **Source:** https://code.claude.com/docs/en/permission-modes (§ Server-side classifier review), plus the CC changelog 2.1.281/282.

### B4. `failure.refusal-billed`: category-aware refusal spend (detector, built with A1)

- **Inputs:**
  - `stop_reason: "refusal"`, `stop_details.category`, `usage`, `usage.iterations` (attempt, fallback), `stop_details.recommended_model`.
  - OTel `claude_code.api_refusal`: `has_category`, `server_fallback_hop`, and `category`, which is only present with `OTEL_LOG_TOOL_DETAILS=1`.
- **Detection rule:** billed pre-output refusals (category ∈ facts list) **or** mid-stream refusals, grouped by repo/team/skill. Flag
  - **refusal loops**: ≥ 2 billed refusals with the same body hash in a session;
  - **uncredited fallbacks**: a retry on another model without the `fallback-credit-2026-07-01` header. This extends the existing `refusal-fallback-no-credit`.
- **Fix sentences:**
  - `reasoning_extraction`: "Stop asking the model to print its reasoning; use adaptive thinking output instead."
  - `frontier_llm`: "Route this workload to a model/deployment it isn't refused on, or use `fallbacks: "default"`; don't blind-retry."
  - All categories: "Retries of a refused prompt are billed each time in these categories."
- **Savings:** billed refusal cost. EXACT once the category is known. When it is redacted (`has_category` true, no `category`), use a range, because `cyber` is unbilled.
- **Source:** refusals page (A1) and https://code.claude.com/docs/en/monitoring-usage (`api_refusal` event).

### B5. `cc.post-compaction-thrash`: re-exploration after compaction (detector)

- **Why:**
  - Compaction can weaken the influence of recent interactions, "increasing blocked actions, repeated exploration, and instability across runs" (arXiv 2608.06503, Aug 2026, S!). The corpus already cites the related 2608.16370.
  - Claude Code now emits `claude_code.compaction` with `trigger`, `pre_tokens`, `post_tokens`, `duration_ms` and `precompute_reuse` (P). Token Bill's OTel adapter maps `compact` only as a lane kind. It does not read the event.
- **Inputs:** compaction timestamps (event, or the transcript's compact boundary); the file paths and commands of Read/Grep/Bash tool calls in the K turns before and after; tokens per call.
- **Detection rule:** after compaction, ≥ X% of the tool calls in the next N turns re-read files or re-run discovery commands already seen in the pre-compaction window. Priced as the input+output tokens of those duplicate calls.
- **Fix sentence:** "Compact with focused instructions (or let the prepared summary be reused), keep durable state in CLAUDE.md/memory, and raise `autoCompactWindow` for this cohort."
- **Savings:** duplicate-call tokens × observed rates. ESTIMATED, upper bound.
- **Sources:**
  - https://code.claude.com/docs/en/monitoring-usage (Compaction event)
  - https://arxiv.org/abs/2608.06503 (S!)

### B6. `copilot.review-personal-auto`: review spend the org cannot switch off (detector)

- **Inputs:** AI usage report review lines (product/workflow path for code review) per PR author and date; PR events (draft, push). The personal settings themselves are not visible through the API (VERIFY).
- **Detection rule:** review credits on draft PRs or on repeated pushes to the same PR, or in repos with no automatic-review ruleset. These can only come from personal settings or manual requests (A5).
- **Fix sentence:** "Ask authors to turn off 'Review new pushes'/'Review draft pull requests' and set personal effort to Lite; ruleset changes cannot override personal auto-review."
- **Savings:** not projected (R13). Show observed credits.
- **Source:** https://github.com/github/docs/commit/db58c0abbd466a401258c61dddb75b17abc65576

### B7. Claude Code OTel event pack: four detectors from events Token Bill does not ingest yet

## (D) Measurement and verification methods worth adopting

1. **Use GA cache diagnostics as default ground truth, and implement the vendor's 2×2 reading** [P].
   - Always send `diagnostics: {previous_message_id}` from the recorder. It is free and "never blocks or fails your request". Store the tri-state (A2).
   - Classify with the doc's matrix:
     - `null` + low reads → expired entry. This is the true TTL signal.
     - `*_changed` + low reads → client bug.
     - `*_changed` + high reads → a late change, low impact.
     - `pending` or `unavailable` → no label.
   - Report Token Bill classifier precision and recall only on the labeled subset.
   - Also check the `anthropic-workspace-id` header of consecutive turns, because a workspace mismatch produces `previous_message_not_found`.
2. **Verify a policy rollout from telemetry, not from config files** [P]. `claude_code.managed_settings_resolved` reports:
   - `sources` and `source_behavior`;
   - `helper.state`;
   - `refused` with `error.type` ∈ {`version_below_minimum`, `policy_invalid`, …};
   - with `OTEL_LOG_MANAGED_SETTINGS`, the redacted settings plus a SHA-256 digest.

   Use the digest as the per-session **treatment indicator** in the existing ITS/DiD verification (`gap-fleet-causal-savings-verification.md`), and `version_below_minimum` as the compliance check for B1. The corpus proposed this in `claude-code.md` §309, but nothing in `tokenbill/` reads the event.
3. **Read the right fields as the right kind of number** [P]:
   - `subagent_completed.total_tokens` is a final-request footprint.
   - `cache_missed_input_tokens` is a byte-length estimate.
   - OpenAI `cache_missed_tokens` and `comparison_reusable_tokens` are estimates.

   None of these is a billing quantity. Mark them `evidence_only` in the evidence schema so no projection multiplies them by a price.
4. **Paired closed-loop continuation for compaction policies** (TRACE, arXiv 2608.06503, S!). Evaluate a compaction or summary policy by forking the *same* environment state and continuing under two policies, then compare billed cost and success. This is cheaper and less noisy than fleet A/B for `cc.autocompact_window` and `cc.compact_on_resume`.
5. **Attribute savings per lever end-to-end, not by compression rate** (arXiv 2609.22114, Aug 2026, S!).
   - The paper decomposes a production compression gateway on Claude Code and Codex sessions into three levers: tool-schema filtering, file-read and tool-output compression, and history summarization.
   - It finds only **tool-schema filtering** "unambiguously and reproducibly positive": a fixed 21K–57K tokens per typical turn, linear in turns.
   - Action: rank `cc.tool_search`/`sdk.defer_loading` above content-compression levers in projections, and require billed end-to-end measurement for any compression lever. This agrees with the corpus's `2607.12161` ("Token Reduction Is Not Cost Reduction").
6. **Treat the harness action space as an eval hypothesis** (arXiv 2609.20804, 2026-09-17, S!). Across 176 matched settings on SWE-Bench Verified and Terminal-Bench 2.1, bash-capable models "can operate effectively with a bash-only interface and achieve substantially lower cost". This is a candidate `needs_eval` lever for SDK/headless agents, not for interactive Claude Code.
7. **Population priors for benchmarks** [P, vendor data]. Anthropic (2026-09-24), March → September 2026 Claude Code data:
   - Claude works 3.3x longer per prompt with >40% more model calls.
   - Context per request grew 2.6x.
   - The input:output ratio went from 189:1 to 324:1.
   - With Opus 5.5, "input that misses the cache decreased by more than 50%".

   Use these as reference ranges in `cc-context-size-driver` and the fleet report.
8. **Maintain an exogenous-event calendar for ITS** (extends DC15):
   - 2026-09-22: Opus 5.5 GA and CC 2.1.280 alias flip.
   - 2026-09-22: OpenAI GPT-6 caching change.

   - 2026-09-24: refusal billing resumes.
